Detection Rules

Rule-based
  1. Each floor has a normal baseline flow and pressure.
  2. Flow is abnormal if it rises more than 30% above baseline (water escaping makes more water flow).
  3. Pressure is abnormal if it drops more than 20% below baseline (a leak lets pressure escape).
  4. NORMAL both readings within limits.
  5. WARNING only one indicator abnormal, or both abnormal but not yet confirmed.
  6. LEAK SUSPECTED both flow and pressure abnormal for 3 consecutive readings. This avoids false alarms from a single odd reading.

These are demonstration thresholds, not validated real-world engineering limits. The system identifies a suspected floor or pipeline branch; physical inspection is needed to confirm the actual leak location.

Future: Physical IoT Hardware

Proposed
  • Hall-effect water flow sensor (e.g. YF-S201) on each floor's branch line
  • Pressure transducer on each floor's branch line
  • ESP32 / Arduino microcontroller collecting readings
  • Wi-Fi / MQTT to send data to a cloud or local server
  • Main water meter at the building inlet for the water balance check
  • Motorised / solenoid valve on each floor for automatic shut-off
  • SMS / app notifications to maintenance staff

Now: Software Simulation

Implemented
  • Seeded 7-day sample history (about 1,000 records) with past incidents and maintenance
  • JavaScript generates realistic live flow and pressure readings
  • Small fluctuations during normal operation
  • Leaks simulated by raising flow and lowering pressure
  • Same rule-based detection logic real sensors would feed
  • Simulated sensor faults (offline sensor link)
  • Dashboard alerts, history, charts and maintenance workflow
  • No hardware connected: no real sensor data is claimed
